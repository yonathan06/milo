# Community UI walkthrough

Screenshots generated by the shared Playwright walkthrough from an isolated synthetic fixture database, with provider credentials blank. They are not live research results.

- [Editable community controls](screenshots/community-controls.png): select Wedding / Family / Company / Professional planner or Custom; edit the brief; choose consumer/professional/mixed audience; select community lanes; optionally discover public leaders. Discord/WhatsApp are unchecked by default. Professional planners remain professional, never a filmmaker preset. With no selected lane, Start is disabled.
- [Run, funnel and audit](screenshots/community-run.png): frozen segment/audience/lanes/leader setting, saved 70/30 criteria and fallback queries; fit coverage and promotion permission; independent processing stages; candidate funnel, discovery versus recovery usage, configured limits, and retained/rejected audit.

Representative flow verified by the shared UI integration scenario:

1. Change to Professional planner, confirm professional audience and planner-focused brief, edit it, and toggle lanes. There is no legacy research mode or creator control. Submitted requests require explicit valid settings.
2. Open a saved wedding fixture run. Confirm its frozen consumer audience/default lanes and saved distinct fallbacks. Inspect the named public founder's role/date/contact citations and separate permission. Missing leaders on other communities are not fit failures.
3. Review/select a row. TanStack Query refreshes affected projections while expanded details and local table state persist. Directory review state updates across views. Only selected/inspected/qualified/reachable/allowed prospects can prepare editable manual drafts; there is no Send action.
4. Filter by Facebook, then clear filters. Provisional source links are labeled as provisional, never “inspected source”; snippet rankings do not establish verified operators/contact/permission or outreach readiness. Local text search/expansion use cached data, not extra fetches. Unverified snippet evidence remains provisional/low-confidence. A Reddit scoring-outage fixture still says Page: inspected, Scoring: failed, not page-blocked.
5. Open Diagnostics: returned/rejected/duplicate/ambiguous/shortlisted/inspection/scoring/leader counts, stage errors, acquisition usage and caps. Rejected candidates stay in audit, not the qualified directory. Deferred or failed stages have explicit Enrich / retry actions; retries use saved evidence and the shared budget.
6. Open the additional authored shell fixture. Its bounded safe stage error reports provider-confirmed truncation, finish reason, configured limit and reported token counts, not raw output. Click Enrich / retry: retained sources replace its historical generic inspection with **Page: failed / unverified**, provisional evidence and deferred leader work. The isolated server has no credentials, so native classification fails closed; the mutation refreshes current stages/labels while preserving local expansion, queries and settled billing. This UI scenario verifies repair and safe refresh, not paid success; the shared native pipeline/persistence scenarios separately verify successful provisional ranking and idempotent recovery with mocked OpenRouter. Missing metadata remains unknown; historical parse errors do not prove truncation.
7. Open the additional authored scope run. Title/boilerplate-only input displays **Needs community evidence** with no numeric community rank. A provisional planning-only result displays **Supported fit score 100/100 / 30% supported weight**, audience_alignment unknown, and an explicit warning that this is not full member-audience alignment. Citations show provisional source plus community-context/description scope, never inspected source. Select the row: mutation invalidation refreshes review state while expanded partial-fit details remain visible and no outreach draft becomes available. A separate authored invalid-demand response displays the safe `unsupported_claim_scope` citation category without its raw output. These are native mocked scenarios, not live quality acceptance.
8. Expand an unscored row: Needs evidence is not a numeric low-fit score. Fit coverage and unknown demand remain explicit; contact availability never implies permission or buying intent.
9. Confirm Delete all prospects. It clears even filtered-out run evidence/candidates/leaders while keeping run/search/budget records. Shared prospects from other runs are retained (persistence scenario).

A historical **partial** run continues to describe the original discovery attempt. Retry refreshes current stage/funnel projections, not the historical lifecycle status. Missing canonical-community context shows needs-community-evidence/deferred stages without a paid scoring request or numeric fit. Supported partial coverage and provisional scope remain visible; a normalized partial score is not a claim of full audience support. Historical completed scores remain historical records, not reassessed results. Ordinary workspace reads/deployment do not initiate shell repair or replay.

The walkthrough also checks no client hydration errors, stable local search without duplicate requests, mutation invalidation, and displayed frozen data. Browser/Node country labels are pinned where their locale catalogs disagree. SSR query clients remain per-request and fresh hydrated data is reused; active planning/queued/running runs poll only while active.
